5. USB 模式切换（核心难点）

这是整个流程中最关键的一步。RTL8851BU 的 USB 设备初始状态是 CDROM/Mass Storage 模式（用于 Windows 安装驱动），需要发送特定 SCSI 命令切换到 WiFi+BT 模式。

5.1 确认当前状态

设备显示为 0bda:1a2b，Product 字符串为 “DISK”，bInterfaceClass 为 Mass Storage (8)。这就是 CDROM 模式。

5.2 尝试 usb_modeswitch（失败）

最常见的思路是用 usb_modeswitch：

结论：usb_modeswitch 的所有标准方法对 0bda:1a2b 均无效。

5.3 成功方案：pyusb 直接发送 SCSI 命令

通过 Python pyusb 库直接向 USB 设备发送 Bulk-Only Transport (BOT) 协议的 SCSI 命令。

原理：USB Mass Storage 设备使用 BOT 协议通信，主机通过 Bulk OUT 端点发送 Command Block Wrapper (CBW, 31字节)，设备通过 Bulk IN 端点返回 Command Status Wrapper (CSW, 13字节)。切换流程分两步：先发 ALLOW MEDIUM REMOVAL（0x1e）解除介质锁定，再发 START STOP UNIT（0x1b）带 Load/Eject 位触发模式切换。

8. 踩坑总结

问题 原因 解决方案
WiFi 驱动编译报 sizeof-array-div 错误 phl_regulation_def.h 第 114 行 sizeof 使用了错误的结构体类型 将 sizeof(struct regulatory_domain_mapping_6g) 改为 sizeof(struct chdef_6ghz)
编译报 arch/aarch64/Makefile: No such file Makefile 默认用 uname -m 得到 aarch64，但内核目录是 arch/arm64/ 编译时显式指定 ARCH=arm64
SSH 编译超时 编译时间超过 SSH 会话超时 使用 nohup + 后台脚本 + 日志轮询
USB 设备始终显示为 CDROM 模式 usb_modeswitch 标准方法对 0bda:1a2b 无效 用 pyusb 发送 SCSI BOT 命令（ALLOW MEDIUM REMOVAL + START STOP UNIT）
蓝牙 hciconfig 无设备 USB 设备未切换模式，BT 接口不可见 先完成 USB 模式切换
蓝牙 rfkill soft blocked 某些操作触发了 rfkill 开关 sudo rfkill unblock all
BLE 扫描报 I/O error rtk_btusb 驱动版本对 LE 命令支持不完整 不影响经典蓝牙，可尝试更新驱动或换用内核 btusb 模块
